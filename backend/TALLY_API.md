# SRF — Tally Outstandings API

For the Tally development team. Tally pushes customer outstanding (pending bill) data to this API; SRF stores it and shows it in its admin panel.

## Connection

| | |
|---|---|
| Base URL | `https://<srf-api-domain>/api/v1/tally` (the exact URL is shown in SRF Admin → Tally Sync) |
| Protocol | HTTPS |
| Content-Type | `application/json` |
| Authentication | `api_key` in the JSON body of the sync request. GET requests (which have no body) send `Authorization: Bearer <API key>`. |
| Max body size | 10 MB, and at most 50,000 bills per request |

The API key is generated by the SRF admin and shared with you separately. If it is regenerated, the old key stops working immediately.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/outstandings/sync` | Push outstanding data |
| GET | `/ping` | Check the URL and key |
| GET | `/outstandings/sync-status` | Check the latest sync, or one sync with `?sync_id=` |
| GET | `/outstandings/customers` | Read back the stored balance per customer, to compare with Tally |

## POST `/outstandings/sync`

Send one entry in `Bills` per pending bill (bill-wise outstanding), as in Tally's *Bills Receivable* report.

```json
{
  "api_key": "<API key>",
  "dealer_name": "Test Dealer",
  "Bills": [
    {
      "bill_number": "INV-001",
      "bill_date": "2026-11-01",
      "customer_name": "ABC Traders",
      "pending_amount": 25000.00,
      "closing_amount": 75000.00
    },
    {
      "bill_number": "INV-002",
      "bill_date": "2026-11-03",
      "customer_name": "ABC Traders",
      "pending_amount": 15000.00,
      "closing_amount": 75000.00
    },
    {
      "bill_number": "INV-003",
      "bill_date": "2026-11-05",
      "customer_name": "XYZ Enterprises",
      "pending_amount": 18000.00,
      "closing_amount": 45000.00
    }
  ]
}
```

### Top level

| Field | Type | Required | Notes |
|---|---|---|---|
| `api_key` | string | Yes | The API key from SRF Admin → Tally Sync |
| `dealer_name` | string | Yes | Must be spelled the same on every sync — it identifies whose outstandings these are |
| `Bills` | array | Yes | Every pending bill. An empty array is valid and means nothing is pending. |

### `Bills[]`

| Field | Type | Required | Notes |
|---|---|---|---|
| `bill_number` | string | Yes | Bill / invoice number (Tally Ref. No.) |
| `bill_date` | date | Yes | Bill date |
| `customer_name` | string | Yes | Tally ledger name of the customer. Keep it the same on every sync. |
| `pending_amount` | number | Yes | Amount still pending on this bill. Positive = receivable (Dr). Negative = credit (Cr). |
| `closing_amount` | number | No | The customer's closing balance in Tally. The same value on every bill of one customer. |

Formats:

- **Dates:** `YYYY-MM-DD`. Tally's `YYYYMMDD` is also accepted.
- **Amounts:** rupees with up to 2 decimals, as a JSON number (`25000.00`) or a string (`"25,000.00"`).
- **Overdue days / age:** not needed. SRF calculates them from `bill_date`.
- **One bill, one entry:** within a request, the same `bill_number` may appear only once per customer.

### Every request is a full sync

Each request must contain *every* pending bill of the dealer as of now. It replaces everything SRF held for that `dealer_name` before; a bill missing from the request is treated as settled.

- The previous data stays live until the request has been fully stored. A request that fails changes nothing.
- A bill with `pending_amount` 0 is ignored.
- Re-sending the same request is safe: the result is the same data.
- Customers are matched to SRF customers by `customer_name`. Customers SRF cannot match are still stored; the SRF admin links them in the admin panel.

### Success response

```json
{
  "success": true,
  "message": "Outstanding data synchronized",
  "sync_id": "SYNC-20261113093000-4F2A1C",
  "dealer_name": "Test Dealer",
  "received_bills": 3,
  "stored_bills": 3,
  "settled_bills": 0,
  "customers": 2,
  "outstanding_amount": 58000.00,
  "unmapped_customers": 0
}
```

`outstanding_amount` is the sum of `pending_amount` and should equal the grand total of Tally's Bills Receivable report. `settled_bills` counts bills sent with `pending_amount` 0. `unmapped_customers` is for information only.

### Error response

```json
{
  "success": false,
  "error_code": "VALIDATION_FAILED",
  "message": "2 problem(s) in Bills — nothing from this request was stored",
  "errors": [
    { "index": 14, "field": "bill_date", "message": "bill_date must be YYYY-MM-DD" },
    { "index": 31, "field": "pending_amount", "message": "pending_amount is required" }
  ]
}
```

`index` is the position of the bill in `Bills`, starting at 0. If any bill in a request is invalid, the whole request is rejected and nothing from it is stored.

| HTTP | `error_code` | Meaning |
|---|---|---|
| 400 | `INVALID_JSON` | Body is not valid JSON |
| 400 | `INVALID_PAYLOAD` | Body is not a JSON object |
| 400 | `VALIDATION_FAILED` | A required field is missing or badly formatted; see `errors` |
| 401 | `UNAUTHORIZED` | `api_key` missing or wrong |
| 413 | `PAYLOAD_TOO_LARGE` | Body over 10 MB |
| 500 | `SERVER_ERROR` | Problem on the SRF side — nothing was changed, retry later |

## GET `/outstandings/sync-status`

Without parameters it returns the most recent sync. Optional: `?sync_id=SYNC-20261113093000-4F2A1C`, `?dealer_name=Test Dealer`.

```json
{
  "success": true,
  "sync": {
    "sync_id": "SYNC-20261113093000-4F2A1C",
    "status": "COMPLETED",
    "dealer_name": "Test Dealer",
    "as_of_date": "2026-11-13",
    "received_bills": 3,
    "stored_bills": 3,
    "customers": 2,
    "outstanding_amount": 58000.00,
    "unmapped_customers": 0,
    "error": null,
    "started_at": "2026-11-13T04:00:00.000Z",
    "completed_at": "2026-11-13T04:00:01.000Z"
  }
}
```

`status` is `COMPLETED` or `FAILED`.

## GET `/outstandings/customers`

The balance SRF currently holds per customer. Parameters: `page` (default 1), `limit` (default 100, max 1000), `dealer_name`.

```json
{
  "success": true,
  "as_of_date": "2026-11-13",
  "total_outstanding": 58000.00,
  "customers": [
    {
      "customer_name": "ABC Traders",
      "pending_amount": 40000.00,
      "closing_amount": 75000.00,
      "bill_count": 2,
      "mapped_to_customer": true
    }
  ],
  "pagination": { "total": 2, "page": 1, "pages": 1 }
}
```

## Quick test

```bash
curl -H "Authorization: Bearer <API key>" https://<srf-api-domain>/api/v1/tally/ping
```

A correct URL and key return `{"success": true, "message": "API key accepted", …}`.

## Suggested schedule

A full sync once or twice a day (for example at 9 am and after closing), or after every billing session. Please confirm what Tally can trigger automatically.
